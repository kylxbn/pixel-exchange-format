## Result

For this probe, Facebook's JPEG output is an exact quantized-DCT match for the standard libjpeg integer path at:

- quality `92`
- sampling `4:2:0`
- baseline, non-progressive JPEG

It does **not** match:

- `cjpeg -dct fast`
- `cjpeg -dct float`

It matches exactly at the coefficient level with:

- `cjpeg -dct int`
- `cjpeg -dct int -optimize`
- Pillow JPEG save
- Pillow JPEG save with `optimize=True`
- ImageMagick
- GraphicsMagick
- libvips

## Exact `cjpeg` recipe

If the goal is to reproduce the **same quantized coefficients** as Facebook for this probe, the key `cjpeg` arguments are:

```bash
cjpeg -quality 92 -sample 2x2,1x1,1x1 -dct int
```

That means:

- `-quality 92`
- `-sample 2x2,1x1,1x1` for `4:2:0`
- `-dct int` for the integer DCT path

If the goal is to reproduce the same **optimized JPEG entropy stream** as Facebook, aside from Facebook's extra ICC `APP2` profile segment, then use:

```bash
cjpeg -quality 92 -sample 2x2,1x1,1x1 -dct int -optimize
```

Important distinction:

- `-optimize` does **not** change the quantized DCT coefficients
- `-optimize` **does** change the Huffman tables and file size
- Facebook's file matches the `-optimize` stream once its extra ICC profile chunk is removed

For a PNG input, one end-to-end example is:

```bash
magick doc/artifacts/facebook-jpeg-encoder/probe.png ppm:- \
  | cjpeg -quality 92 -sample 2x2,1x1,1x1 -dct int -optimize \
      > /tmp/facebook-like.jpg
```

## Stronger structural result

After stripping Facebook's extra APP2 marker, the remaining JPEG byte stream is byte-for-byte identical to:

- `cjpeg_int_opt.jpg`
- `magick.jpg`
- `pillow_opt.jpg`

The Facebook file differs from those local files by an added ICC profile segment:

- marker: `APP2`
- payload length reported by `jpeglib`: `470`
- total file size delta vs `cjpeg_int_opt.jpg`: `474` bytes

That 474-byte delta matches the APP2 marker overhead plus payload, which strongly suggests:

1. The underlying entropy-coded JPEG stream is the same as optimized libjpeg-family output.
2. Facebook adds or preserves an ICC profile chunk on top of that stream.

## Best current hypothesis

Facebook is using a libjpeg-family encoder that behaves like:

- integer DCT
- optimized Huffman tables enabled
- baseline 4:2:0 JPEG at libjpeg Q92 tables
- ICC profile embedded as APP2

## Browser canvas results

### Firefox canvas export

`firefox-roundtrip.jpg` used:

- baseline, non-progressive JPEG
- the same libjpeg-family Q92 quantization tables
- `4:4:4` sampling, not `4:2:0`
- `APP0` only, no ICC profile

This means Firefox's built-in canvas encoder is **not** following the same path as Facebook for this test, even though the quality tables look related.

### Chromium canvas export

`chrome-roundtrip.jpg` used:

- baseline, non-progressive JPEG
- `4:2:0` sampling
- the same libjpeg-family Q92 quantization tables
- `APP0` plus an ICC `APP2` profile

Most importantly:

- its quantized DCT coefficients are an exact match for Facebook
- its coefficients are also an exact match for `cjpeg -dct int -optimize`
- after stripping non-JFIF APP markers, its JPEG byte stream is identical to Facebook's and to `cjpeg -dct int -optimize`

The remaining visible difference is the embedded ICC profile:

- Facebook embeds `uRGB`
- Chromium embeds a Google `sRGB` profile

So for this probe, Chromium's canvas JPEG export produces the same compressed JPEG stream as Facebook.

## Remaining ambiguity

This experiment does **not** distinguish between several frontends that produce the same optimized libjpeg-family output, including:

- `cjpeg -dct int -optimize`
- Pillow with `optimize=True`
- ImageMagick

GraphicsMagick produced the same coefficients but a slightly different JFIF header in this environment, so it is a weaker binary-level match.

## Next ideas

If we want to narrow the implementation further, useful follow-up probes would be:

- a probe with a known ICC profile embedded in the source PNG to test whether Facebook preserves, replaces, or synthesizes the profile
- mozjpeg and jpegli candidate runs, if installed
- targeted tests for chroma downsampling filter details on non-neutral source color management inputs
