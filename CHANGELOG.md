# Changelog

## 2026-05-19 - PXF v301 (`a374effe2baf3850ad6e99e8f8ae4bcdb21a3c79` -> `65763e1545408aedadf4454f230d5a5bd08eb059`)

This change range marks the transition from PXF v300 to v301 and focuses almost entirely on the audio path. The first major shift is a new JPEG-tuned coefficient mapping strategy. Instead of relying on the previous default zigzag layout, the codec now defines `q92pm1` and `q92pm8` mapping presets derived from ImageMagick/libjpeg quantization tables, with `q92pm8` becoming the new default. That change is backed by a new preset-generation script and checked-in ranking notes, which makes the mapping reproducible and easier to reason about. In practical terms, audio energy is now placed into coefficients in an order that better reflects the JPEG quantization behavior the format is trying to survive.

The other headline change is a stereo-aware redesign of SBR metadata and reconstruction. PXF now encodes as format version `301`, while the decoder is updated to accept both `300` and `301` so older files remain readable. In v301, the legacy SBR processing-mode bits are repurposed into a 3-bit stereo cue that describes how high-frequency content between mid and side channels should relate to one another. The encoder now analyzes stereo rows jointly, derives these cues per subgroup, and can lock patch modes when the channels are strongly coherent. The decoder mirrors that by using a joint SBR synthesis path for compatible v301 mid/side pairs, coupling the stochastic high-frequency reconstruction so stereo placement survives the round-trip more reliably.

The final pass in this range is about cleanup and trustworthiness at the edges. Silent or near-silent high-frequency regions are now treated explicitly as silence instead of being misread as weak noisy texture, and SBR synthesis no longer injects quiet pseudo-random hiss when the source band is effectively empty. The SBR test suite grows alongside these changes, covering legacy and v301 bit layouts, stereo cue analysis, stereo projection behavior, patch-mode locking, and silence handling. The decoder UI is updated too, replacing the old processing-mode readout with the new stereo-cue interpretation when inspecting v301 audio rows. Taken together, these commits make the format more JPEG-aware, more stable in stereo, and noticeably less likely to produce subtle high-frequency artifacts.
